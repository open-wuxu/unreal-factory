# 上海外滩 v3.0 · 基于真实地理数据的 1:1 三维城市

- 日期：2026-11-05
- 状态：待评审
- 位置：`material/上海外滩v3.0/`
- 前置版本：`material/上海外滩v2.0/`（保留其渲染与交互体系，重写世界生成层）

## 1. 意图与为什么

v2.0 是一个完全程序化、视觉完整的城市景观，但河道、建筑和道路都是虚构的。
v3.0 要在 v2 的渲染与交互基础上，把"虚构城市"替换为"真实地理城市"：

- 真实黄浦江岸线与水域形态；
- 真实道路、桥梁、滨江空间；
- 真实建筑轮廓、位置与尽可能真实的高度；
- 以米为单位、1:1 的世界比例；
- 每个高度值和几何来源都可追溯，估算值明确标注。

**这不是测绘级数字孪生。** 公开数据无法提供上海全部建筑的实测高度，也无法提供
授权清晰的四大地标精细模型。v3.0 的目标是"基于真实数据的可信重建"，不是
"冒充实测数据"。

## 2. 目标 / 非目标 / 反目标

### 目标

1. 场景范围覆盖外滩—陆家嘴核心区，所有空间关系与真实地理一致。
2. 岸线、道路、建筑轮廓来自真实公开数据，不以随机几何替代。
3. 建筑高度按来源分级：实测/标注 > 公开模型估算 > 工程估算，全部可追溯。
4. 四大地标按公开尺寸 1:1 重建，位置来自真实轮廓。
5. 保留 v2 的昼夜、水体、材质、后期与交互质量，并增加建筑属性查看与城市漫游。
6. 运行时完全离线，不依赖 Cesium ion、地图瓦片或任何在线服务。
7. 交付可运行的 Vite 项目、数据处理脚本、来源清单和精度验收报告。

### 非目标

- 不做全球或全上海范围；不做 GIS 分析工具；不做在线地图底图。
- 不引入 CesiumJS（已确认）。
- 不追求测绘级精度；不把估算值描述为实测值。
- 不追求四大地标之外的每栋建筑都有实测高度。
- 不做真实交通仿真、实时船舶 AIS 或天气系统。

### 反目标（即使技术上能跑，也算失败）

- 随机生成或手工摆放建筑来"看起来像上海"。
- 把 3D-GloBFP / 栅格估算的高度写成真实高度。
- 使用来源不明的地标模型或贴图。
- 场景比例、岸线或地标位置明显偏离真实地理。
- 运行时依赖外部服务，导致离线打不开。

| 决策 | 结论 | 来源 |

## 4. 场景范围与坐标系

### 范围

- 西至：外滩历史建筑群西侧约 121.475E
- 东至：陆家嘴核心区东侧约 121.515E
- 南至：延安东路—东昌路一带约 31.225N
- 北至：苏州河—北外滩南缘约 31.255N

覆盖外滩、陆家嘴、北外滩南缘、苏州河汇入段，包含四大地标与外白渡桥。
南浦大桥、杨浦大桥在本范围外，不纳入 v3.0；范围内桥梁按 OSM `bridge=yes` 建模。

### 坐标转换

- 原点 `ORIGIN = { lon: 121.495, lat: 31.240, height: 0 }`。
- 实现 `WGS84 → ECEF → ENU`，输出：
  - `x = east`（向东为正）
  - `y = up`（向上为正）
  - `z = -north`（向南为正，沿用 v2 的 Three.js 坐标习惯）
- 运行时所有坐标已是局部米制，不再出现经纬度。
- 场景半径约 2.5 km，float32 精度足够；不做分块浮动原点。

### 高程

Copernicus DEM 是 **DSM（含建筑、植被、桥梁表面）**，不是 DTM。直接采样会让塔楼
底部落在自己屋顶上，因此必须先生成"近似地面"：

1. 对 30 m DEM 做 5×5 中值滤波，再做 3×3 均值平滑，得到近似 DTM。
2. 将滤波结果限制在 3–8 m 的合理地面高程区间；江面区域单独按水域掩膜处理。
3. 建筑基底、道路、桥梁、树木一律采样滤波后的地面，不采样原始 DSM。
4. `y=0` 定义为原点附近**陆地区域滤波后高程的中位数**，不是某个建筑街区处的原始
   DSM 值。所有高程只使用相对差值，不混用 EGM2008 大地高与场景 y。
5. 水面高程 = 水域多边形内滤波地面高程的中位数；水面与岸线的高差在数据阶段核对
   后写入 `config.js`，并在精度报告中标注为"近似水位"。
6. 若滤波后某处仍受桥面/大型结构影响，以周边 90 m 半径内的地面中位数兜底。

这套规则由 `tools/process_dem.py` 实现；精度报告需给出滤波前后的高程差统计。

## 5. 数据源与真实性分级

### 数据源

| 数据 | 来源 | 许可 | 用途 |
| --- | --- | --- | --- |
| 建筑轮廓、道路、岸线、水域、树木、桥梁 | OpenStreetMap（主 API 按瓦片抓取） | ODbL 1.0 | 几何底图 |
| 建筑高度补全 | 3D-GloBFP 上海瓦片（Figshare 65 MB） | CC BY 4.0 | 普通建筑高度 |
| 地形 | Copernicus DEM 30m | Copernicus 条款 | 地形网格 |
| 四大地标尺寸 | OSM 轮廓 + 公开建筑资料 | — | 参数化建模 |
| 低层高度交叉校验 | Evolving Cityscape（可选） | CC0 | 只做校验，不作为主数据 |

### 真实性分级（每栋建筑写入 `heightSource`）

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| `osm:height` | OSM 明确标注高度 | 直接使用，UI 显示"实测标注" |
| `osm:levels` | OSM 楼层数 × 3.2 m | 使用，UI 显示"按层估算" |
| `globfp` | 3D-GloBFP 逐栋高度 | 使用，UI 显示"模型估算" |
| `estimated` | 无任何数据，按类型/面积估算 | 使用，UI 显示"工程估算"，并在验收报告中计数 |
| `official` | 四大地标按公开尺寸 | 使用，UI 显示"公开尺寸" |

`estimated` 建筑数量必须尽量小，并在数据清单中列出比例。

### 建筑轮廓来源与去重规则

- **OSM 优先**：所有 OSM 建筑轮廓保留，作为权威轮廓。
- **GloBFP 补全**：仅当 GloBFP 建筑同时满足以下条件时才加入：
  1. 面积 ≥ 60 m²；
  2. 高度 ≥ 3 m；
  3. 质心不在任何 OSM 建筑多边形内；
  4. 与最近 OSM 建筑质心距离 > 10 m；
  5. 与 OSM 建筑的多边形重叠面积 < 其自身面积的 30%。
- **ID 规则**：OSM 建筑 `osm:way/<id>` 或 `osm:relation/<id>`；
  GloBFP 补全建筑 `glo:<gridId>:<featureIndex>`。
- 每栋建筑写入 `source`（`osm` / `globfp`）与 `heightSource`，UI 可区分显示。
- 补全建筑默认显示，可在 UI 中切换隐藏；精度报告单列其数量与面积分布。

### 估算比例验收

- `estimated` 指：无 OSM `height`、无 OSM `building:levels`、且无 GloBFP 匹配的建筑。
- **目标 ≤15%**（按渲染建筑数量计）。
- **硬上限 30%**：超过则 Phase 1 判定不通过，必须补充数据、改进匹配或人工核对，
  不得直接进入 Phase 2。
- 比例、数量和分布写入 `manifest.json` 与精度报告。

### 高层与超高层规则

- **需要覆盖的对象**：高度 ≥ 100 m 的建筑。
- **优先级**：OSM `height` > OSM `building:levels × 3.2` > 人工核对值 > GloBFP。
- **人工核对范围**：仅四大地标，以及 OSM 中已有名称但缺高度的 ≥100 m 塔楼；
  不做全量逐栋人工查证。人工值必须写入 `tools/tower-heights.json`，并附来源链接。
- 不满足上述条件的 ≥100 m 建筑，使用 GloBFP 值但必须在 UI 标记"模型估算"，
  且在精度报告中单列，避免陆家嘴天际线被系统性压低却不被看见。

### 实测精度（已用 OSM 真值验证）

- 3D-GloBFP：659 栋匹配，相关系数 0.776，MAE 16.9 m；5–30 m 建筑偏高约 43%，
  100 m 以上偏低约 20–23%；上海中心最近匹配 338 m（真值 632 m）。
- Evolving Cityscape：284 栋匹配，MAE 28.1 m；200 m 以上仅为真值的 0.19，
  不能用于高层；只作为低层交叉校验。
- 结论：**地标和超高层一律用 OSM/公开尺寸覆盖，不采用模型估算。**

## 6. 数据处理管线

所有脚本放在 `tools/`，输出放在 `public/data/`。原始 OSM XML、GloBFP shapefile、
DEM 原始瓦片不入库，只提交处理结果、下载地址、校验和与来源说明。

```
tools/
├── fetch_osm.mjs          # 按瓦片抓取 OSM 主 API，限速、重试、缓存
├── parse_osm.mjs          # 节点/way/relation → 建筑、道路、水域、树木、桥梁
├── process_globfp.py      # 读取 GloBFP shapefile，输出逐栋高度 CSV
├── process_dem.py         # 裁剪 Copernicus DEM，输出 heightmap JSON
├── build_dataset.mjs      # 合并、匹配高度、投影 ENU、简化、输出 GeoJSON
└── verify_dataset.mjs     # 数据完整性、范围、地标位置、高度分布检查
```

### 管线步骤

1. **抓取 OSM**：按 `121.475–121.515E, 31.225–31.255N` 切 0.01° 瓦片，约 12 块。
   附 `User-Agent`，请求间加延迟；结果缓存到 `tools/.cache/`（不入库）。
2. **解析**：
   - 建筑：`building=*` 的 way 与 multipolygon relation；处理内环；丢弃面积 < 20 m²。
   - GloBFP：读取上海瓦片，按核心范围裁剪，保留 `Height` 与面积；只作为补全源。
   - 道路：`highway=*`；保留 `bridge`、`tunnel`、`layer`、`lanes`、`width`。
   - 水域：`natural=water`、`water=river`、`waterway=riverbank`；合并为连续水面。
   - 树木：`natural=tree`、`natural=tree_row`。
   - 桥梁：`bridge=yes` 的道路段，单独成组。
3. **轮廓合并与高度匹配**：
   - OSM `height` 优先；`building:levels × 3.2` 次之。
   - 用 GloBFP 逐栋高度，按质心 30 m 内最近匹配；面积比需在 0.5–2.0 之间，
     避免把塔楼匹配到旁边的小棚屋；匹配距离写入数据。
   - GloBFP 独有建筑按 §5 的去重规则补入，高度取 GloBFP 值。
   - 无匹配时按建筑类别给默认值，并标记 `estimated`。
   - 四大地标用公开高度覆盖。
   - 合并结果必须通过 §5 的估算比例检查。
4. **投影与简化**：WGS84 → ENU；Douglas-Peucker 简化，容差 0.5 m；保留原始面积。
5. **输出**：
   - `city.json`：建筑、道路、水域、桥梁、树木、地形、manifest。
   - `manifest.json`：范围、原点、数量、来源、生成时间、脚本版本、校验和。
   - 单文件目标 < 20 MB（gzip 前），gzip 后 < 6 MB，便于本地加载。
6. **校验**：`verify_dataset.mjs` 检查字段完整性、坐标范围、地标距离、高度范围、
   NaN、重复 ID、文件体积；不通过则构建失败。

### 道路宽度

优先使用 OSM `width`；否则用 `lanes × 3.5 m`；再否则按等级默认值：
motorway 30、trunk 24、primary 20、secondary 14、tertiary 10、residential 8、
service 5、pedestrian 5、footway 3、cycleway 2.5（单位 m）。
默认值在数据清单中标注为"按等级估算"。

## 8. 视觉与交互

### 视觉

- PBR 建筑立面，程序化窗格 albedo + emissive；按高度带和建筑类型共享材质。
- 真实岸线水面，保留 v2 的反射、菲涅尔、夜间灯影与贴岸泡沫。
- 四种时间状态：白天 / 日落 / 蓝调时刻 / 夜景，统一插值天空、光照、雾、曝光、
  泛光、水面和窗灯。
- 真实阴影：单主方向光 + 2048² PCF，仅在太阳方向变化时重绘。
- 建筑属性面板显示：名称、高度、高度来源、楼层、轮廓面积、OSM ID、数据等级。
- 数据等级图例：可切换显示"估算高度"建筑，用低饱和色标出。

### 交互

- 自由旋转、缩放、平移（OrbitControls）。
- 高空航拍视角、四大地标快速定位、外滩建筑群视角。
- 城市漫游：指针锁 + WASD + 地面跟随，视高 1.7 m；碰撞可选，首版不做建筑碰撞。
- 点击建筑查看属性。
- 时间切换、自动环绕、重置视角、键盘快捷键。
- 加载进度与 WebGL 2 回退提示。

### 装饰性元素（明确标注，不作为真实数据）

- 船只：沿 OSM 黄浦江中心线航行，船型与班次为装饰。
- 车流：沿 OSM 道路行驶，流量为装饰。
- 路灯、栏杆、滨江设施：按道路/岸线程序化布置，位置为工程近似。
- 树木：优先使用 OSM 点位；缺失段可程序化补植并标注。

## 9. 性能

- 目标：Apple Silicon + Chrome，1920×1080 下 60 fps；集成显卡 ≥ 30 fps。
- 建筑几何按材质/高度带合并为少量 `BufferGeometry`；静态物体不逐帧更新矩阵。
- 预计渲染 8,000–10,000 栋建筑（OSM + GloBFP 补全）；目标三角形 < 250 万。
- 建筑拾取使用合并网格 + 面索引 → 建筑 ID 映射，避免每栋一个 Mesh。
- 纹理共享，禁止为每栋建筑生成独立 Canvas 贴图。
- 像素比上限 1.5；阴影贴图 2048²；水面反射分辨率独立且可降级。
- 数据加载 < 3 s（本地），总几何三角形目标 < 250 万，draw calls < 300。
- 提供 `?debug=stats` 显示 draw calls / triangles / 内存。

## 11. 验收与精度报告

交付 `docs/accuracy-report.md`，至少包含：

1. **位置精度**：四大地标渲染位置 vs OSM/官方坐标，误差（米）。
2. **尺度检查**：江面宽度、外滩建筑间距、道路宽度、建筑高度 vs 数据源。
3. **高度覆盖**：按 `heightSource` 统计建筑数量与比例；`estimated` 目标 ≤15%、
   硬上限 30%；GloBFP 补全建筑单列。
4. **已知误差**：GloBFP 超高层低估、DEM 30m、道路宽度估算、装饰元素。
5. **数据来源清单**：文件、URL、许可、下载日期、校验和。
6. **浏览器验证记录**：每个阶段的实际截图与检查项，不以代码检查代替渲染验证。

`verify_dataset.mjs` 的自动检查必须全部通过，才能进入下一阶段。

## 12. 分阶段实施

| 阶段 | 内容 | 完成标准（必须浏览器验证） |
| --- | --- | --- |
| 1. 数据与坐标 | 抓取、解析、匹配、投影、输出、校验脚本 | `city.json` 通过校验；`estimated` ≤30%；灰盒场景中四大地标位置与外滩/陆家嘴相对关系正确 |
| 2. 城市骨架 | 地形、岸线、水面、道路、桥梁 | 江面连续、岸线贴合、道路连通、桥梁不悬空 |
| 3. 建筑与地标 | 建筑挤出、高度分级、四大地标 | 建筑不重叠、不穿水、地标高度与位置正确 |
| 4. 材质与光照 | 立面、窗灯、水面、天空、四时相 | 四种时间状态切换正常，无材质/曝光异常 |
| 5. 交互与性能 | 属性面板、漫游、LOD、精度报告 | 交互可用；帧率达标；报告完成 |

每阶段结束后必须在浏览器中实际渲染、截图并记录；代码检查不能替代渲染验证。

## 14. 已知风险与缓解

| 风险 | 缓解 |
| --- | --- |
| OSM API 限速/不稳定 | 瓦片化、限速、重试、缓存；预处理结果入库 |
| 水域多边形分段、接缝 | 多边形合并；中心线兜底；渲染前检查连通性 |
| GloBFP 超高层低估 | 地标与 OSM 高层用官方/标注高度覆盖 |
| 72% 建筑无高度 | 分级标注；GloBFP 匹配；`estimated` 目标 ≤15%、硬上限 30%；UI 明确显示 |
| GloBFP 补全轮廓与 OSM 重叠 | 质心/距离/面积比三重去重；重叠 >30% 拒绝；UI 可切换隐藏 |
| 地标模型无授权来源 | 参数化重建，标注"非测绘模型" |
| 数据体积过大 | 简化、丢弃小建筑、只提交派生数据 |
| 许可合规 | `DATA-SOURCES.md` + 页面署名 + 数据文件许可说明 |
